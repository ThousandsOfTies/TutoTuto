# TutoTutoの軽量化案

2026-09-06に、認証監視・採点履歴修正後の同じソースと依存環境で比較。
以下の軽量化は提案段階で、アプリのソースには未反映。

## 1. 使用するSNSアイコンだけを取り込む

共通ライブラリの `src/constants/sns.ts` が
`import * as SimpleIcons from 'simple-icons'` と動的な名前参照を使い、
使用しないブランドもビルド成果物に含めている。
現在使う15アイコンを名前付きimportに変更し、IDから対応するアイコンを選ぶ。
Amazonの既存フォールバックは維持する。

一時的なVite変換プラグインでこのimportだけを変更し、
通常と同じkidsモードの本番ビルドを実行した。単位は10進MB。

| メインJavaScript | 現状 | アイコン限定後 | 削減 |
|---|---:|---:|---:|
| ファイルサイズ | 8,832,720 bytes | 3,602,565 bytes | 約59% |
| gzip圧縮後 | 3,167,817 bytes | 1,037,834 bytes | 約67% |

画面・機能を削らず、通信量とJavaScriptの解析負荷を減らせる。
実端末での起動時間は未測定なので、起動速度が同じ割合で改善するとは限らない。
実装時は定義済みSNS、独自URL、Amazonの表示を確認する。

## 2. HEIC変換と教材編集を必要なときに読み込む

`src/utils/imageProcessor.ts` はHEIC変換ライブラリを常時importしている。
HEIC/HEIFを取り込む関数内で動的importする。
教材編集画面も `React.lazy` 等で分割し、PDF加工・画像編集の依存が
初期画面へ静的import経由で残らないようにする。

効果は、通常の教材一覧・学習開始で読み込むコードと初期メモリの削減。
削減量は未測定。初めて変換・編集する際は追加読み込みが必要になる。
読み込み中表示と失敗時の再試行を設ける。

現在のPWAは全JavaScriptを事前キャッシュするため、
単にファイルを分割するだけでは全体の初回通信量は減らない。
初期動作に必要な資産は事前キャッシュを維持し、
変換・編集の追加コードは利用時のキャッシュへ分ける。
その場合、未使用機能を初めてオフラインで開く動作には制限が生じるため、
既存のオフライン利用方針と合わせて判断する。

## 3. StudyPanel内の責務を分ける

ページ切り抜き、採点要求と履歴保存、描画保存、画面遷移を
それぞれ独立した関数・hookへ分離する。
今回のようなページ情報の受け渡しや非同期処理の検証を容易にする。

主な効果は修正の安全性と保守性。ファイルを分けるだけでは
実行速度や配信サイズは原則改善しない。
再描画の削減は実端末で遅い操作を測定した後、その箇所に絞って行う。

優先順位は1、次に2、3は関連機能の修正と合わせて段階的に進める。
